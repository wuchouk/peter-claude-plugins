# OpenMemory 寫入流程

如果 OpenMemory MCP 可用（`add_memories` 工具存在），執行以下寫入。如果不可用，跳過並告知使用者。

## 去重檢查

寫入前先用 `search_memory` 搜尋客戶名稱，檢查是否已有該專案的日誌指標或教訓。如果已存在相同教訓（語意相同），跳過該筆不重複寫入。

> **背景**：`custom_fact_extraction_prompt` 已設定，每次寫入最多提取 3 個事實，單一事實會保持原樣不拆分。因此一條教訓一次呼叫的策略仍然正確。

## (a) 日誌指標

寫入一筆摘要，讓其他工具能發現此日誌：

```
開發日誌：{客戶名} — {專案名稱}。
產品描述：{description}。
開發時間 {起始日期} ~ {結束日期}。
完整日誌：/Users/cubie/Documents/給Peter的檔案/devlogs/{檔名}
```

## (b) 獨立教訓

把「教訓與下次改進」和「技術困難點 → 學到什麼」中的每條**具體**教訓獨立寫入。

**關鍵規則：每條教訓必須獨立呼叫一次 `add_memories`，禁止把多條合併成一段文字寫入。**

格式（每筆一條）：
```
[開發教訓] {具體教訓}（來源：{客戶名} 專案 {日期}）
```

例如：
- `[開發教訓] Excel TwoCellAnchor 圖片跨列跨欄時，需保留 row_span/col_span 才能正確定位（來源：IP Winner 2026-02-27）`
- `[開發教訓] Streamlit Cloud iframe sandbox 限制 JS 執行，需用 declare_component + postMessage 繞過（來源：IP Winner 2026-02-27）`

### 篩選標準

- ✅ 具體的、可在未來重用的技術教訓
- ❌ 泛泛的心得（如「要多測試」「要早點確認」）

## (c) 寫入驗證

每次 `add_memories` 呼叫後，**必須**用 `search_memory` 驗證寫入是否成功。

### 驗證流程

1. 每筆 `add_memories` 完成後，立即用 `search_memory` 搜尋剛寫入的關鍵字（客戶名或教訓中的關鍵技術詞）
2. 檢查搜尋結果是否包含剛寫入的內容（語意匹配，不需完全一致）
3. 記錄驗證結果：✅ 已驗證 / ❌ 未找到

### 驗證失敗處理

- 重試一次 `add_memories`（相同內容）
- 再次用 `search_memory` 驗證
- 如果仍然失敗，標記為 ❌ 並在最終摘要中列出失敗的項目，提醒使用者手動檢查

### 搜尋策略

- 日誌指標：搜尋 `{客戶名} 開發日誌`
- 教訓：搜尋教訓中最具辨識度的關鍵字（如技術名詞），避免用太泛的詞搜尋
